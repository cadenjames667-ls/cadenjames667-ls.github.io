The Pantry

A real-time kitchen inventory manager. Add groceries, queue recipe links, and see changes sync instantly across every device signed into the same account — powered by Firebase Firestore and Auth underneath a static, serverless frontend.

How It's Made

Pantry is a single static HTML page — no build step, no backend server of its own. Everything that needs to persist or sync across devices goes through Firebase: Firestore holds the data, and Firebase Auth (email/password) gates access and determines whose pantry you're looking at.

Each signed-in account gets its own "pantry space," keyed by Firebase UID. Adding an item, queuing a recipe URL, or removing something writes directly to Firestore, and a live onSnapshot listener pushes that change back out to every open tab or device in real time — no manual refresh, no polling.

Architecture
graph LR
    Browser[Static HTML/JS on GitHub Pages] -->|email/password| Auth[Firebase Auth]
    Auth -->|UID| Browser
    Browser <-->|live onSnapshot sync| DB[(Firestore)]

There's no application server in the middle — the browser talks directly to Firebase. That keeps the whole app deployable as static files on GitHub Pages, with Firebase providing the only "backend" pieces: identity and a real-time database.

Data Model
erDiagram
    PANTRY_SPACE ||--o{ ITEM : contains
    PANTRY_SPACE ||--o{ RECIPE : contains

    PANTRY_SPACE {
        string spaceId PK "usually the owner's Firebase UID"
    }
    ITEM {
        string id PK
        string name
        string qty
        string cat
        timestamp createdAt
    }
    RECIPE {
        string id PK
        string url
        timestamp createdAt
    }

Items and recipes live under pantries/{spaceId}/items and pantries/{spaceId}/recipes. By default spaceId is just the signed-in user's UID, which is what makes "Share Pantry" possible — it copies a link with a ?pantry=<uid> query param that re-points any other signed-in viewer's session at that same space.

Key Engineering Decisions
  • Auth UID doubles as the partition key. No separate "create a pantry" step exists — signing up automatically gives an account its own Firestore space, keyed by the UID Firebase already assigns.
  • Share-by-link, not a permissions system. Pointing another signed-in user at your space is just a URL parameter, not a real ACL. It's flagged clearly in the app and here — it's convenient, not secure.
  • Demo Mode never touches Firestore. It's a fully separate client-side code path with hardcoded sample data, so visitors can try every interaction (add, remove, search, filter) without creating an account or writing to the real database.
  • Legacy data migration on first connect. Pantry started as a localStorage-only app before Firestore was added. The current version auto-imports any of that old local data into Firestore the first time a browser connects, instead of discarding it.
