Furnder

A swipe-based furniture discovery app. Paste a product link from Wayfair, IKEA, Amazon, or almost any retailer, and it automatically pulls the image and title to build a Tinder-style swipe deck — liked items land in a Firestore-backed collection you can revisit anytime.

How it's made

Furnder is a static HTML/JS page backed by a single open Firestore collection — there's no user accounts or sign-in, every visitor shares the same furniture deck. Pasting a product URL triggers a call to Microlink, a public Open Graph metadata API, which scrapes the target page's title and preview image without the browser needing to fetch and parse the retailer's HTML directly (most retail sites block that from a browser anyway).

The swipe deck itself is built on plain pointer events rather than a drag/gesture library — mouse and touch input both drive the same handler, translating and rotating the top card with a CSS transform as you drag, and animating it off-screen once a swipe threshold is crossed.

Architecture
graph LR
    Browser[Static HTML/JS on GitHub Pages] -->|paste product URL| Microlink[Microlink API]
    Microlink -->|title + image| Browser
    Browser <-->|read / write| DB[(Firestore: furniture)]

Two external calls, no server of its own: Microlink for one-shot metadata scraping when an item is added, and Firestore for everything that needs to persist — the swipe deck, swiped/liked state, and the liked-items grid.

Data model

        number addedAt

A single flat collection, furniture. Each document represents one piece of furniture through its whole lifecycle: added with swiped: false, then flipped to swiped: true plus liked: true/false the moment someone swipes on it. The swipe view queries for swiped == false; the Liked view queries for liked == true.

Key decisions
  • One document, one lifecycle. Rather than moving an item between collections as it gets swiped, its state just changes in place — simpler queries, no risk of an item existing in two places at once.
  • Metadata fetch is fire-and-forget, not blocking. If Microlink fails to find a preview image (rate-limited, unsupported site, network error), the item can still be added with just a name — the UI degrades instead of dead-ending.
  • No drag library. The swipe gesture is ~40 lines of pointer-event math (start/move/end, threshold check, CSS transform), which keeps the page dependency-free and easy to follow end to end.
